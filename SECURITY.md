# Security Policy

## Reporting a vulnerability

Please do not publish exploit details for a live issue before maintainers have had a chance to investigate. Open a private vulnerability report through GitHub's **Security → Advisories** flow when it is available for this repository, or open a minimal public issue asking for a private reporting channel without including sensitive details.

## Security design

- Runs without administrator privileges.
- Restricts its local API to the loopback address and an internal per-install token.
- Requires an allowed Spotify HTTPS origin.
- Verifies process creation identity before changing or restoring working-set limits.
- Saves original Windows limits before applying a limit and attempts recovery on shutdown and next launch.
- Starts every role at a 38 MB ceiling in Custom mode, with a 4 MB absolute floor and an identity-specific learned safe floor; Audio stays at 25 MB or more, a visible-background renderer at 38 MB, and Audio can adapt upward to 60 MB under sustained load.
- Sends no telemetry.
- Does not disable antivirus, SmartScreen, Windows Firewall, or execution-policy controls.

## Release trust

Release artifacts include SHA-256 checksums generated by CI. Checksums prove that a downloaded file matches the published artifact; they do not, by themselves, prove who published it or that the source code is safe. Windows code signing and provenance attestations should be enabled when maintainers have the required credentials and workflow configuration. An unsigned build may still show SmartScreen warnings.
